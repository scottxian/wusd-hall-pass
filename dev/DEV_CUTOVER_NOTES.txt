NEW — NOVEMBER 6: SCOPED SPECIAL DAYS AND REUSABLE ROOM GROUPS
- Both School Admin DEV and Master Admin DEV now include Room Groups in the
  Room Scheduling Manage dropdown. Admins may create/edit/delete named sets
  of active classrooms (e.g. Middle School, Sixth Grade).
- Special Days now accepts a schoolwide default Schedule Type (including
  Primary) with group/individual classroom exceptions.
- Precedence: teacher daily override > specific room date exception >
  room group date exception > schoolwide date type > room Primary schedule.
- Overlapping selected groups are rejected for the same room unless that
  room has a direct override, which takes precedence.
- Day-specific group memberships are SNAPSHOTTED at save. Editing a group
  later does not silently modify dates already saved.
- Preview shows all active rooms' effective bell schedules and changes for
  each selected date. Existing dates support Skip or Replace.
- A date save is atomic: both schoolwide and per-room records update together.
  Removing the date removes all its group/room exceptions too.
- New DEV tables: room_groups, room_group_members,
  school_day_room_overrides. Row-level security is enabled and function
  execution is restricted to the service role via verified staff Admin calls.
- DEV staff Edge Function and public Edge Function both resolve scoped
  dates using the same precedence rules.
- SQL save/skip/remove and room-group lifecycle were tested against the
  DEV test school; the QA date and room group were removed afterward.
- Browser admin workflows still need human sign-in/UI testing. No
  additional production changes are authorized or implemented.


NOVEMBER 9, 2026 — SPECIAL DAYS DATE-FIRST UI (DEV ONLY)
- Redesigned Special Days in School Admin and Master Admin; existing
  configured dates appear first, with Edit/Remove actions.
- Date selection automatically checks already-loaded school scheduling
  state. Existing dates load saved schoolwide type, note, group selections,
  and room-specific schedules. New dates default to Primary.
- Editor labels are now "All other classrooms follow" and "Different
  Schedules". The Who picker supports named Room Groups or selected rooms,
  with a single Which Schedule picker. Editing a saved date shows Save
  Changes instead of Create Special Day.
- Group membership changes do not silently rewrite saved dates. When a
  group changed after the date was saved, the original affected rooms are
  shown as individual room selections to preserve the saved configuration.
  Missing/inactive saved rooms or unknown schedule types block editing.
- The preview groups high-level assignments together; detailed per-room
  bell schedules remain visible in an expandable table. Missing schedules
  appear explicitly and block Save.
- For a single date, the interface automatically adds or updates without
  a Skip/Replace dropdown. For multiple dates, any existing dates require
  an explicit "Keep existing"/"Replace existing" radio choice and show
  the exact affected dates and proposed actions before Save is enabled.
- Right before Save, the admin client refetches scheduling state and
  rejects a stale preview if selected dates, room assignments, or group
  membership changed. This reduces accidental overwrites; an atomic
  database compare-and-swap has not been added.
- Existing adminSaveScopedSpecialDays backend action is retained;
  no schema changes or production deployment were performed.
- Tests: both inline scripts parse, key elements exist uniquely.
  Focused in-code simulated tests passed for saved-date loading, a
  new-date Primary default, room vs group priority, changed group
  membership preservation, missing schedule identification, explicit
  multi-date conflicts, and stale-data rejection.
- Authenticated full-browser testing remains required before rollout.
  Supabase DEV access for this chat currently returns "You do not have
  permission to perform this action"; no direct database verification
  was possible during this UI update.

NOVEMBER 9, 2026 — SIMPLIFIED SINGLE-FORM SPECIAL DAYS REDESIGN (DEV ONLY)
- Both DEV School Admin and DEV Master Admin now present one Special Day
  per date with an assignment list. Each assignment targets the Entire
  School, a named Room Group, or selected individual classrooms.
- The schoolwide type is inferred from an Entire School assignment;
  otherwise the day defaults to Primary. The backend still receives
  defaultType plus explicit group/room overrides in the established payload.
- Priority remains classroom > room group > schoolwide > normal Primary.
  Duplicate room rules and conflicting overlapping group assignments are
  rejected; specific room assignments can resolve group overlaps.
- A compact draft summary counts rooms by effective Schedule Type.
- Optional Preview is a standalone popup with a full classroom breakdown;
  it is NOT necessary to save. Save automatically checks each effective bell
  schedule and explains missing assignments.
- New dates save directly. Editing an existing date loads its saved rooms
  and requests explicit confirmation before replacing that date's data.
  The pre-save state fingerprint guard, existing privileged API action,
  and atomic scoped-date backend operation are unchanged.
- Group memberships are saved as exact room snapshots. Existing dates with
  changed group membership load their original members as individual room
  assignments, protecting earlier scheduling decisions.
- Removed the redundant New Special Day button and the mandatory preview
  step. Legacy multi-date inputs remain dormant/hidden for rollback.
- Static checks: inline JavaScript parses in both pages, IDs are unique,
  and no obsolete Save-stage elements remain. Simulated assignment tests
  covered school/group/room priority, overlapping groups, missing schedules,
  saved group snapshots, stale data protection, and saving without preview.
- Full authenticated DEV browser testing remains required. Group 4 Test 6
  stays paused until the user is ready to restart.
- No production files, production data, Supabase schema, or Edge Functions
  were modified.
